# Pass2 Prompt A/B Notes (2026-05-05)

This note summarizes the prompt/context experiments run against the live
teacher endpoint `http://10.16.12.175:8000/v1` on `data/agent_v5/batch1`.

## Scope

- Goal: understand how pass2 observation quality changes when we vary:
  - text memory format
  - text-vs-visual ordering
  - full-timeline vs summary-only memory
  - stronger current-chunk-first instruction
  - repair prompt structure
- Constraint: keep the setup close to the student/runtime:
  - sliding visual window
  - text memory preserved conceptually
  - compressed summaries preserved

## Main results

### 1. Older structured/prose memory formats are unstable

From `live_top3_40_20260505_0827/summary.json`:

- `structured_text_first_forward`
  - `chunks=120`
  - `repair_attempted=73`
  - `repair_rejected=72`
  - `hard_stale_runs=7`
  - `max_exact_run=33`
  - `max_near_run=37`
- `structured_text_first_reverse`
  - `repair_attempted=45`
  - `repair_rejected=43`
  - `hard_stale_runs=8`
  - `max_near_run=39`
- `structured_minfields_text_first_forward`
  - `repair_attempted=40`
  - `repair_rejected=37`
  - `hard_stale_runs=8`
- `structured_images_first_forward`
  - better than text-first structured, but still stale
- `prose_text_first_forward`
  - `max_exact_run=35`
  - `max_near_run=40`

Conclusion:
- full-memory prose / ledger-like formats strongly encourage stale repetition
- repair mostly fails to rescue these outputs

### 2. Student-like tag memory: summary-only is clearly best

From `student_tags_ab_20260505_0858/summary.json`:

- `student_tags_summary_only_text_first_forward`
  - `videos=3`
  - `chunks=120`
  - `repair_attempted=0`
  - `repair_rejected=0`
  - `hard_stale_runs=0`
  - `max_exact_run=1`
  - `max_near_run=1`
- `student_tags_last2_text_first_forward`
  - `videos=3`
  - `chunks=120`
  - `repair_attempted=23`
  - `repair_rejected=20`
  - `hard_stale_runs=7`
  - `max_exact_run=18`
  - `max_near_run=18`

Conclusion:
- summary-only tag memory is much cleaner than summary + last2 raw thinks
- recent raw thinks reintroduce stale continuation bias

### 3. Full-timeline tag memory is still hard

Partial run state from `fulltag_matrix_20260505_0927/chunks.jsonl`:

- `fulltag_mild_timeline_text_first_forward` completed `120` chunks
- `fulltag_strong_timeline_text_first_forward` reached `114` chunks before interruption

Observed behavior:
- mild full-timeline still generates repeated current-looking prose that is
  effectively copied from earlier chunks
- stronger wording removes some explicit continuity words like
  `continues/remains`, but repeated sentence skeletons still appear

Conclusion:
- the problem is not only the word `continues`
- full-timeline raw think memory itself pulls the model back into earlier
  sentence templates

## Visual inspection notes

Two repeated segments were manually inspected:

- `29M_i_-Qxg4` vacuum segment around chunks `5-12`
- `dA5GBOjQgeg` farrier segment around chunks `34-39`

Findings:

- Some segments are visually similar across neighboring chunks
- But the repeated outputs are often too template-like to be explained by
  static frames alone
- In the farrier case, later text sometimes drifts back toward older action
  wording that is not the best direct description of the current two frames

Conclusion:
- repetition is partly caused by low visual novelty
- but prompt/input structure still pushes the model toward text-memory
  continuation

`max_strict` prompt intent:

- text memory is naming-only, never continuation context
- older visual frames are coarse context only
- only the current two frames can supply the current action/state
- even same-object cases must be rewritten from current frames in fresh wording

## Practical takeaways so far

- `summary-only tag memory` is the cleanest tested setup
- `full-timeline tag memory` is not solved by simple tags alone
- stronger prompt wording helps, but raw full-timeline text memory still
  appears to bias generation heavily
- repair should be pure current visual when the goal is to correct the
  current chunk rather than continue memory
