# v12.14 — Integration status (as of 2026-05-03)

## MemAgent vs ReMemR1 — what we vendored is compatible with BOTH

ThinkStream's v12.14 vendored from `/tmp/refs/ReMemR1/recurrent/`, but
side-by-side `diff` confirms ReMemR1 is a fork of MemAgent and the
recurrent framework is essentially identical. So our vendor is
compatible with both:

| Recurrent infra file | MemAgent vs ReMemR1 |
|---|---|
| `interface.py` (AsyncOutput, AsyncRAgent base) | ✅ **byte-identical** |
| `async_generation_manager.py` (run_llm_loop) | ✅ **byte-identical** |
| `async_utils.py` (ChatCompletionProxy) | ✅ **byte-identical** |
| `tool.py` | ✅ **byte-identical** |
| `generation_manager.py` (sync version) | differs 37 lines (cosmetic) |
| `utils.py` (chat_template, padding) | differs 4 lines (cosmetic) |
| `impls/async_memory.py` | ✅ identical |
| `impls/memory.py` | ReMemR1 renamed → `memory_revisit.py` + added TF-IDF retriever + `<recall>` template hooks |

| ray_trainer.py | MemAgent vs ReMemR1 |
|---|---|
| Recurrent dispatch core (~150 lines if/else inside `fit()`) | ✅ functionally same |
| Reward extras (`compute_action_rewards`, `compute_format_rewards`, `compute_action_reweights`, `update_validate_metrics`) | ❌ ReMemR1-only — NOT in MemAgent |
| Best-checkpoint-by-val-metric save logic | ❌ ReMemR1-only |
| `run_llm_loop` vs `run_llm_loop_revisit` (entry name) | trivial rename |
| Total diff: ~164 lines | mostly ReMemR1's added reward features |

**Direct implications for v12.14**:
- `AsyncStreamingVideoAgent.rollout()` returning
  `AsyncOutput(conversations, sample_index, final_mask, timing_raw, metrics)`
  satisfies the contract used by **both** MemAgent and ReMemR1.
- The `multi_modal_data: List[Optional[Dict]]` extension we added is
  net new — MemAgent and ReMemR1 are both **text-only**. ThinkStream
  is the first streaming-video user of this framework.
- MemAgent's reward path (`recipe/r1/reward_score.py`) is just a
  data-source-dispatch — the action-/format-level reward heuristics
  are ReMemR1-specific. v12.14 first version follows MemAgent's
  simpler "outcome-only via final_mask broadcast" baseline; ReMemR1's
  extras are an optional v12.15+ enhancement.

## ray_trainer integration — DONE (Option B chosen + executed)

We picked **Option B** (extend `AgentLoopBase.run()` to return
`List[AgentLoopOutput]`) and shipped it across 4 phases + 4 P0/P1
audit-driven fixes.

### Phase delivery

| Phase | Commit | What |
|---|---|---|
| 1 | `1620080` | `AgentLoopBase.run() → Union[AgentLoopOutput, list[AgentLoopOutput]]`; `AgentLoopWorker.generate_sequences` flattens, writes `sample_index` + `final_mask` to batch |
| 2 | `299c366` | ~~`ray_trainer` reward broadcast~~ → REMOVED in Phase 4 (wrong credit assignment: same scalar across siblings → standard GRPO within-group variance=0 → advantage=0 with rollout.n=1) |
| 3 | `25b194b` | `streaming_agent_loop.py` dispatch — env flag `THINKSTREAM_RECURRENT_MODE=stitched\|recurrent`; per-action `AgentLoopOutput` carries `ts_action_index / ts_n_actions_in_traj / ts_action_chunk_idx` |
| 4 | `409e802` | MemAgent / ReMemR1-aligned trainer: `original_batch` save → swap+reindex → trajectory-level reward extract → `compute_1D_grpo_advantage` by uid → `sample_index` broadcast → tile across response_length × `response_mask` |

### Phase 4 — 4 P0/P1 fixes (audit-driven)

1. **Pad-once-mask-through FSDP** (P0): pad batch + reward_tensor +
   reward_extra to `actor_rollout_wg.world_size`; set
   `response_mask=0` for padded rows; **never unpad**. Padded rows
   ride through old_log_prob / ref / values / update_critic /
   update_actor with mask=0 → 0 contribution to loss/adv. Mirrors
   MemAgent `no_padding_mask` but more conservative (verl 0.4's
   `_update_actor` also goes through `DataProto.chunk()`, requires
   integer divisibility).
2. **`reward_extra_infos_dict` padding** (P0/P1): pad arrays via
   head-replication so `non_tensor_batch` length matches `batch`
   length after pad. Without this, the
   `batch.non_tensor_batch.update(reward_extra_infos_dict)` write
   in the adv block silently created TensorDict / non_tensor_batch
   length mismatch.
3. **`reward_tensor` padding semantic** (P1): changed from tail
   replication (`reward_tensor[-1:].expand(N)`) to head replication
   (`reward_tensor[:N]`) to match `pad_dataproto_to_divisor()`.
4. **Telemetry naming** (P1/P2): renamed
   `recurrent/discarded_nonfinal_reward_*` →
   `recurrent/nonfinal_action_score_*` to honestly reflect that
   non-final action scores include cumulative outcome/timing/silent
   from common_extras (not just per-action format/spam).

### Activation (EXPERIMENTAL — start with 2-GPU debug)

```bash
THINKSTREAM_RECURRENT_MODE=recurrent \
MAX_RESP_LEN=4096 \    # ← per-action cap, NOT stitched 32768
MULTI_Q=1 THINKSTREAM_MAX_RECALL_PER_CHUNK=1 \
bash verl/recipe_thinkstream/run_thinkstream_grpo.sh
```

`MAX_RESP_LEN` matters: `AgentLoopWorker` pads each action's response
to `rollout.response_length`
(`verl/verl/experimental/agent_loop/agent_loop.py:736`). At sum(K_i)
actions × 32768 tokens, dense responses/rm_scores/advantages/log_probs
explode in memory and cross-rank communication even though attention
runs no-padding. ~4096 is the right per-action cap for ThinkStream.

### Still NOT validated

- Real Ray/FSDP multi-GPU `actor_rollout_wg` / `ref_policy_wg`
  dispatch on padded batch
- Actor loss + grad_norm + clipfrac stability with broadcasted
  advantages + masked padded rows over many steps
- format/spam reward in recurrent comes from final action's
  `solution_str` only (NOT a stitched trajectory) — defensible
  compromise documented inline in `ray_trainer.py` Phase 4d block
